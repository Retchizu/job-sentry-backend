# TICKET-006: Evaluation summary and benchmark protocol

This document is the release-gate narrative for the **3-class** phase6 fused model (`HybridFusedClassifier`: DistilBERT → BiLSTM → fusion head). Training metrics in `artifacts/models/phase6_fused/fused_meta.json`; row-level benchmark outputs are recorded in `artifacts/models/phase6_fused/validation_merged_test.json` (generated by `scripts/evaluate_fused_on_merged_test.py`).

## Benchmark protocol

- **Split**: `artifacts/data/processed/merged_test.csv`, **n = 3104** (15% holdout, stratified on `risk_class`, seed 42). Class counts: legit 2423, warning 549, fraud 132 — see `artifacts/data/processed/merged_splits.summary.json`.
- **Inference**: Same path as production — `FusedScamPredictor.from_artifact_dir` → batched `predict_risk_distribution` / argmax over softmax triples (see `app/fused_predictor.py`, `app/risk_labels.py`).
- **Multiclass metrics**: sklearn `classification_report`, confusion matrix on `risk_class` vs predicted class; **macro-F1**, **weighted-F1**, **one-vs-rest AUC** (three classes).

### Binary comparison (legacy baselines)

Legacy **binary** models in `artifacts/models/phase6_merged/merged_test_metrics.csv` report accuracy / precision / recall / F1 / ROC-AUC on a **fraudulent vs not** task (merged dataset). The fused model is trained for **three** classes (legit / warning / fraud). They are **not** the same optimization target.

**Ground truth for binary columns below**: `fraudulent == 1` in `merged_test.csv` (132 positives on this split).

**Predicted positive — two definitions** (pick the comparison that matches your product question):

| Definition | Rule | Role |
| --- | --- | --- |
| **Fraud-only** | `argmax` class **2** (fraud) | Closest to “predicted fraudulent” in a strict sense. |
| **Any elevated risk** | `argmax` in **{1, 2}** | Treats warning + fraud as “not legit”; **not** comparable to `fraudulent` alone — expect low precision vs `fraudulent` because many warnings are not in the fraudulent=1 set. |

**Indicative numbers** (same artifact checkout; regenerate via script):

| Model | Notes |
| --- | --- |
| Merged LR | From `merged_test_metrics.csv`: accuracy 0.9894, F1 0.9755, ROC-AUC 0.9993 |
| Merged RF | F1 0.9581, ROC-AUC 0.9995 |
| Merged XGB | F1 0.9916, ROC-AUC 0.9999 |
| **Fused 3-class** (multiclass) | Accuracy **0.922**, macro-F1 **0.833**, weighted-F1 **0.921**, OVR AUC **0.950** |
| **Fused → binary (fraud-only)** | vs `fraudulent`: precision **0.73**, recall **0.69**, F1 **0.71** (see `validation_merged_test.json` → `binary_vs_fraudulent__pred_fraud_only_argmax_2`) |

**Limitation**: Published `merged_test_metrics.csv` figures are only **indicative** unless those baselines were re-run on the **exact** `merged_test.csv` revision used here; if the merged file or labelling changed, recompute baselines on the current split for an apples-to-apples table.

## Strengths

- **Strong overall ranking**: OVR AUC **0.950** on three classes on `merged_test` matches `test_auc` in `fused_meta.json`.
- **Macro-F1 ~0.83**: Reasonable balance across classes despite rarity of fraud (132 / 3104 in test).
- **Legit precision**: Large legit support; confusion matrix shows most legit rows stay on the diagonal (see `validation_merged_test.json` / notebook §Final validation).
- **Contract**: Native **softmax triple** per post; no thresholding required for default `POST /predict` (TICKET-005).

## Risks

- **Class imbalance**: Fraud is rare; small absolute changes in fraud confusion cells move percentages quickly.
- **Warning vs fraud**: Off-diagonal confusion between class 1 and 2 is expected when language overlaps; review FP/FN examples in `artifacts/ipynb/phase6_hybrid_fused.ipynb` (Final validation section) and the confusion matrix (e.g. fraud→warning mass).
- **Domain shift**: Models trained on historical postings may degrade on new geographies, roles, or scam tactics.
- **Operations**: DistilBERT + LSTM on CPU is usable for evaluation but **GPU** is recommended for production throughput; large batches are capped by `JOBSENTRY_MAX_BATCH_SIZE`.
- **Load / perf**: Full production load tests are an optional follow-up (not in TICKET-006 scope).

## Downstream integration

- **Clients expecting a single P(scam) or binary `predicted_scam`**: The default API returns a **full 3-way softmax** and `predicted_class` / `predicted_label` from argmax. For scalar binary workflows, `app.risk_labels.map_binary_to_risk` maps P(scam) into legit/warning/fraud using `JOBSENTRY_WARN_THRESHOLD` / `JOBSENTRY_FRAUD_THRESHOLD`; that path is **not** the default for `POST /predict`.
- **Semantics**: Probabilities are **softmax** masses (sum ~1), not one-hot.
- **Field renames**: Legacy `scam_probabilities`, `predicted_scam`, `threshold` → see migration paragraph in [README.md](../../../README.md).
- **Failure modes**: Missing or broken artifacts → startup error if `JOBSENTRY_PHASE6_FUSED_DIR` is set; unset dir → **503** on predict. Batch over max size → **422**.

## Artifact versioning

- **`artifact_version`** in `artifacts/models/phase6_fused/fused_meta.json` (e.g. `2026-04-20`) is the human-readable release tag; optional **`git_commit`** may be added when exporting from the training notebook.
- Operational convention: ship a directory like `phase6_fused-<artifact_version>/` in storage and point env vars at it.
